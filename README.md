# NV Measurement Console

这是一个参考 LabOne 交互方式的 NV 色心测量系统原型，当前前端已经迁移到 `Vite + React + Mantine + Plotly`。

## 项目结构

- `backend/`：FastAPI 后端，负责设备发现、连接、参数保存和模拟数据
- `frontend/`：Vite React 前端，负责页面路由、表单、图表和交互
- `main.py`：后端启动入口

## 前端页面

- `/device`：设备连接页，扫描并连接锁相和微波源
- `/lockin`：锁相设置页，按通道配置参数并显示实时 X/Y/R 曲线
- `/microwave`：微波设置页，配置 CW、扫频和 FM 调制
- `/odmr`：ODMR 扫描页，支持软件同步和 Aux1 电压映射两种模式
- `/current`：电流测量页，使用 FM 一次谐波 `R=|X+jY|` 的“双瓣-谷-双瓣”结构识别物理共振、X/Y 复数 b/g 投影鉴频、左右独立受限 PID、局部/全频重捕获、时间对齐 Δf 和实时电流换算

## PID 双峰连续跟踪参数调节指南

连续跟踪先通过 FM 一次谐波 R 谱的双瓣中央谷确认左右两个物理共振峰，再用锁相输出
\(Z=X+jY\) 的局部复数斜率计算频率误差。左右峰分别由受限 PID 跟踪，
最后把两个峰对齐到同一时刻，计算：

\[
\Delta f=f_R-f_L
\]

所有调参应以实测的单峰半高全宽 `Γ = FWHM` 和同一峰的实际更新周期
`Tu` 为基准。不要只按照界面默认值判断是否合适。

### 调参前准备

1. 用完整 ODMR 扫描确认搜索范围内有且只有需要跟踪的一对峰，并记录左右峰的
   FWHM、峰深和初始劈裂。
2. 搜索步进建议不大于 `Γ/5`，窄峰或低信噪比时使用 `Γ/8～Γ/10`。
3. 如果仪器能够同时读取原始或低通后的荧光 DC，配置“独立 DC/峰存在性通道”；
   `-1` 表示没有独立 DC，此时使用 `R` 代理并依靠周期斜率验证，抗假锁能力较弱。
4. “每点稳定等待”必须覆盖锁相低通的稳定时间。后端实际等待时间取
   `用户设置、5 × 锁相时间常数、5 ms` 三者中的最大值。
5. 先短时间记录静止峰，观察频率误差噪声、实际更新率、模型 R² 和正交残差，
   再开始提高闭环带宽。

### 推荐起始值

下面的值适合初次闭环测试，不代表所有线宽和信噪比下的最终值：

| 参数 | 推荐起始值 | 说明 |
| --- | ---: | --- |
| 复数模型/斜率探测偏移 | `0.1～0.2 × Γ` | 当前默认 `250 kHz` |
| 每点稳定等待 | `≥ 5 × 锁相时间常数` | 代码还保证至少等待 `5 ms` |
| 每点平均次数 | `1` | 噪声较大时提高到 `3～5`，会降低跟踪速度 |
| Kp | `0.2～0.45` | 无量纲，先从小值开始 |
| Ki | `0`，之后增加到 `0.01～0.05 /s` | 负责消除长期静差 |
| Kd | `0 s` | 只在确有快速过冲且信噪比足够时启用 |
| 微分滤波时间常数 | `0.1 s` | Kd 为 0 时该参数不起作用 |
| 抗饱和反算增益 | `1 /s` | 对应约 1 秒的积分回拉时间尺度 |
| 单周期最大校正 | `0.1～0.25 × Γ` | 应小于峰的线性捕获区 |
| 积分项限幅 | `0.25～0.5 × Γ` | 不应越过峰身份边界 |
| 失锁偏差阈值 | `0.5～0.8 × Γ` | 必须处于可信线性范围内 |
| 最大变化率 | 实际最大峰速的 `2～5` 倍 | 同时要与单周期最大校正相匹配 |
| 最小复数模型 R² | `0.7` | 干净数据可提高到 `0.85～0.95` |
| 正交残差限值比例 | `0.5` | 越小越严格 |
| 斜率验证间隔 | 每峰 `20` 次访问 | 快速漂移或相位变化时缩短 |

例如单峰 FWHM 为 `2 MHz`，可以从以下设置开始：

```text
探测偏移          250 kHz
Kp                0.30
Ki                0
Kd                0
微分滤波时间常数  0.10 s
反算增益          1.0 /s
单周期最大校正    300 kHz
积分项限幅        600 kHz
失锁偏差阈值      1.2 MHz
```

### 推荐调节顺序

#### 1. 先调采集质量

- 关闭积分和微分：`Ki=0`、`Kd=0`。
- 如果 X/Y 抖动明显，优先增加稳定等待；仍然较差时再增加平均次数。
- 复数模型 R² 低，先检查扫频步进、锁相时间常数、FM 调制深度、峰对比度和
  探测偏移，不要先提高 PID 增益。
- 探测偏移过小会使左右两点差异淹没在噪声中；过大会超出峰心附近的线性区，
  或受到另一个峰污染。

#### 2. 只调 Kp

- 从 `Kp=0.1～0.2` 开始，给共振频率一个可控的小扰动。
- 逐步增加 Kp，直到峰能够快速返回，同时没有持续的左右振荡。
- 一旦出现连续振荡或误差符号交替放大，把 Kp 降低约 `20%～30%`。
- 如果 PID 长时间处于限幅状态，不要继续增加 Kp；先检查最大校正、最大变化率、
  稳定等待和峰是否已经离开捕获区。

#### 3. 再加入 Ki

积分项用于消除缓慢漂移、模型偏置和固定静差。当前实现中：

\[
T_i\approx\frac{K_p}{K_i}
\]

例如 `Kp=0.45`、`Ki=0.03 /s` 时，积分时间尺度约为 `15 s`。

- 从 `Ki=0.01 /s` 开始逐渐增加。
- 误差长期偏在同一侧时，可以适当增加 Ki。
- 出现数秒到数十秒的慢振荡、解除限幅后明显反冲时，应减小 Ki。
- 积分限幅应小于单峰的有效捕获范围，并留出左右峰身份保护余量。

#### 4. 最后决定是否需要 Kd

微分项会放大测量噪声，而且锁相低通和左右峰交替采样本身已经引入延迟，因此
ODMR 跟踪通常先保持 `Kd=0`。

只有在 Kp、Ki 已经稳定，但快速峰移动仍有明确过冲时，才尝试很小的 Kd。
微分滤波采用一阶低通：

\[
\alpha=\frac{\Delta t}{\tau_D+\Delta t}
\]

建议把微分滤波时间常数 `τD` 设为约 `2～5 × Tu`，再根据噪声调整：

- `τD` 太小：D 项抖动、微波频率出现高频跳动；
- `τD` 太大：D 项反应滞后，无法抑制快速过冲；
- `Kd=0` 时，`τD` 的设置不影响输出。

#### 5. 设置输出限幅和抗饱和

PID 原始指令经过捕获范围、硬件范围、单步校正、变化率和峰身份边界限制后，
才得到实际频率指令。反算抗饱和使用：

\[
I \leftarrow I+\Delta t\left[-K_i e+
K_{\mathrm{aw}}(f_{\mathrm{applied}}-f_{\mathrm{raw}})\right]
\]

其恢复时间尺度约为：

\[
T_{\mathrm{aw}}\approx\frac{1}{K_{\mathrm{aw}}}
\]

- 默认 `1 /s` 是稳妥起点。
- 解除限幅后仍长时间向错误方向运动，可提高到 `2～5 /s`。
- 解除限幅时出现明显回拉或振荡，应减小到 `0.2～0.5 /s`。
- 设置为 `0` 只关闭反算，条件积分暂停和积分项绝对限幅仍然有效。

### 失锁与重捕获参数

| 参数 | 默认值 | 调节原则 |
| --- | ---: | --- |
| 进入可疑的坏样本数 | `1` | 噪声较大时可设为 `2` |
| 进入重捕获的坏样本数 | `3` | 过小会频繁重扫，过大会延迟恢复 |
| 确认锁定的好样本数 | `3` | 提高可减少假恢复，但恢复更慢 |
| 饱和失锁计数 | `5` | 连续触碰限幅达到该次数后判定无法正常跟随 |
| 重锁增益渐入样本数 | `5` | 重捕获后逐步恢复 PID，过小容易再次冲出 |
| 局部扫描点数 | `17` | 窄峰或低信噪比时增加 |
| 局部扫描初始宽度 | `1 × Γ` | 峰跳变较大时增大 |
| 局部扫描扩展倍数 | `2` | 每次失败后扩大局部范围 |
| 局部扫描最大扩展次数 | `3` | 全部失败后进入全频重新扫峰 |
| 最大自动重扫次数 | `5` | `0` 表示不限制次数 |

频繁在 `TRACKING` 和 `SUSPECT` 之间切换，通常说明质量阈值过严、等待不足或
信噪比较差；频繁进入 `LOST` 但局部扫描总能立即找回，通常说明失锁计数过小、
PID 增益过大或最大变化率过低。

### 复数模型质量参数

- **最小 R²**：模型初始化时的线性拟合质量。提高后更可靠，但弱信号可能无法启动。
- **正交残差限值比例**：实时复数信号偏离模型方向的容忍度。相位或背景易变化时
  可以适当放宽；过度放宽会增加假锁风险。
- **实时斜率验证间隔**：定期测量峰心两侧，验证斜率幅值和相位。间隔越短，
  模型更新越及时，但会降低有效输出速率。
- **斜率验证最大年龄**：超过该时间还没有得到有效验证时，不再认为旧模型可靠。
- **斜率幅值比例和最大角度变化**：用于发现峰形、增益或锁相相位发生显著变化。
  只有确认硬件相位本身会缓慢漂移时才应放宽。

### 时间对齐和快速峰移动

左右峰是顺序测量而不是同一时刻采样。速度预测会把两个峰外推到共同时间再计算
Δf，因此最大峰速、最大加速度和外推时限必须符合真实系统：

- 速度滤波时间常数太小会把频率噪声当成运动，太大会跟不上快速变化；
- 最大速度和最大加速度应略高于已知物理上限，不要无限放大；
- 最大外推时间应大于正常的同峰访问周期，但明显小于“旧数据仍可接受”的时间；
- Δf 不确定度超过阈值时，电流输出会标记为无效，而不是继续外推。

### 常见现象与处理

| 现象 | 优先检查或调整 |
| --- | --- |
| 频率点高频抖动 | 增加稳定等待/平均次数，减小 Kp、Kd，增大微分滤波时间 |
| 峰附近持续来回振荡 | 减小 Kp；若为慢振荡，再减小 Ki |
| 长期存在同方向静差 | 在模型质量正常的前提下逐步增加 Ki |
| 快速变化时总是落后 | 减小不必要的等待/平均，提高 Kp 或最大变化率，检查微波源捷变速度 |
| 快速变化后明显过冲 | 减小 Kp、Ki；必要时加入很小的 Kd |
| 长时间显示 PID 饱和 | 检查峰是否超出捕获区；增大物理允许的限幅，或降低增益 |
| 解除饱和后恢复太慢 | 增大抗饱和反算增益 |
| 解除饱和后出现反向冲击 | 减小 Ki、积分限幅或反算增益 |
| 模型 R² 低 | 调整探测偏移、稳定等待、扫频步进、锁相相位/FM 深度 |
| 离开共振后仍显示锁定 | 优先接入独立 DC 通道，缩短斜率验证间隔，收紧残差/斜率阈值 |
| 左右峰跳到同一个峰 | 增大峰身份保护和最小可分辨间隔，检查初始双峰是否真正可分辨 |
| Δf 有尖峰而单峰曲线正常 | 检查时间对齐参数、速度上限、同峰访问周期和不确定度阈值 |

### 跟踪时间瓶颈分析

连续跟踪页面会按“耗时分析报告间隔”周期性输出滚动统计。时间分析只读取高分辨率
计时器，不改变微波源的 `:FREQ` 控制方式、锁相设置、稳定等待或后台采样行为。

| 指标 | 包含内容 | 数值较大时优先处理 |
| --- | --- | --- |
| 微波 SCPI 写频 | Python 调用 VISA `resource.write(":FREQ ...")` 的返回耗时 | 检查 LAN/USB/GPIB 接口、VISA 后端和信号源远程响应 |
| 显式稳定等待 | 每次写频后代码实际 `sleep` 的时间 | 核对后端缓存的时间常数、带宽和跟踪等待设置 |
| Zurich 设备锁等待 | 跟踪线程等待后台 `poll()` 释放设备锁的时间 | 后续考虑跟踪期间暂停普通曲线轮询或改为共享连续数据流 |
| Zurich 单点读取 | `demod.sample()` 本身的同步调用耗时 | 检查 LabOne Server、接口和采样方式，后续考虑从订阅缓冲区取样 |
| 计算/调度/其他 | 总采集时间减去上述阶段 | 检查线程调度、平均次数、独立 DC 二次读取和前后端负载 |

页面同时显示：

- 单频点采集 P50/P95；
- 完整左右双峰周期 P50/P95；
- 根据周期中位数计算的实测更新率；
- 各阶段平均耗时及占比；
- 自动判定的第一瓶颈；
- 跟踪实际使用的通道、Demod、锁相时间常数、带宽和滤波阶数；
- 启动时直接查询的 Zurich 实际低通参数，并标记它是否与后端缓存不一致；
- 后台 LabOne `poll()` 是否运行及其记录窗口；
- 微波源 `*IDN?` 和 VISA 地址。

仪器规格中的“800 µs 跳频”通常表示仪器收到命令或硬件触发后，RF 输出进入规定
频率误差范围的时间。它不包含电脑线程调度、VISA/LAN 传输、后台设备锁等待、
Zurich 读取和双峰顺序测量，所以不能直接换算成界面更新率。本页面的
“微波 SCPI 写频”也只测到 `resource.write()` 返回，无法单独证明 RF 已在该时刻
完全稳定；完整链路应结合显式稳定等待和实测 ODMR 响应判断。

诊断时建议先保持参数不变运行至少 `50～100` 个双峰周期，再看 P50/P95：

- P50 高、P95 接近 P50：存在稳定的固定瓶颈；
- P50 较低、P95 很高：存在设备锁竞争、网络/VISA抖动或周期性斜率验证；
- “稳定等待”占比最高：才适合继续缩短锁相时间常数或等待时间；
- “设备锁等待”占比最高：调整100 Hz带宽不会明显提高更新率；
- “微波 SCPI 写频”占比最高：再评估 Keysight List/Manual Point 或外部触发跳频；
- “Zurich 单点读取”占比最高：优先改为连续订阅数据流，而不是继续提高PID增益。

### 长时间电流数据保存

连续跟踪默认启用长期记录，默认保存间隔为 `1 s`。这里的 1 秒不是把 PID 更新率
降到 1 Hz：PID 仍按硬件允许的最高闭环速率运行，记录器只把该秒内的高频跟踪点
聚合成一行。因此 13 小时实验约产生 `46,800` 行，Excel 可以直接处理。

- 页面可设置“保存长期电流数据”“保存间隔”和“实验标签”。
- 每个保存间隔记录电流均值/标准差/不确定度、`fL`、`fR`、`Δf`、共模频率、
  有效比例、样本数、左右锁定状态、失锁原因、重扫次数、质量分数和实测更新率。
- 后端每行写入 `data/current_tracking/<会话>/current_tracking_data.csv` 后立即
  `flush`，每 60 行再执行一次磁盘同步；即使 Excel 尚未导出，CSV 仍是恢复源。
- `metadata.json` 保存完整跟踪参数、锁相通道、微波源 ID 和会话状态，并使用原子
  替换避免只写入半个文件。
- 停止、到时结束、异常或失锁终止时自动生成 Excel；运行期间也可点击
  “下载 Excel 快照”，不会停止 PID。
- Excel 包含 `Summary`、`Data`、`Parameters` 三张表。`Data` 保持数值和时间类型，
  可直接画图或做长期稳定性统计。
- 任何 CSV 写盘异常都会主动停止实验并显示错误，避免界面仍在跑但长时数据已经丢失。

长时间运行前建议先做 10～30 分钟试跑，并确认磁盘空间、Windows 休眠/自动更新、
USB/LAN 省电和设备通信稳定。当前跟踪任务仍与 WebSocket 会话绑定：刷新或关闭页面
会安全停止并封存记录，而不是在无人监控时继续下发微波频率。若需要真正无人值守，
下一步最值得加入的是“后端独立任务 + 页面断线重连”，其次是磁盘空间/设备心跳告警、
温度或参考传感器同步记录、手动事件标记和断电后的会话恢复。

### 电流标定注意事项

- 连续跟踪只使用“物理峰心跟踪”产生的 \(\Delta f\) 标定点，不混用旧的单路
  过零点标定。
- 至少需要两个不同已知电流的有效标定点，建议覆盖实际测量范围并增加重复点。
- 默认输出为电流幅值；没有外部方向信息时，单靠劈裂通常不能确定电流正负。
- 超出标定 Δf 范围、双峰任一侧失锁、时间对齐超时或不确定度超限时，电流输出
  会被标记为无效，不进行外推。
- 运行过程中新增标定点后，需要停止并重新启动连续跟踪，后端才会加载新的拟合系数。

## 启动方式

先启动后端：

```bash
python -m pip install -r requirements.txt
python main.py
```

再启动前端开发服务器：

```bash
cd frontend
npm install
npm run dev
```

默认访问：
